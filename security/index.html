Security at Agent Research

Last updated 2026-10-05

Encryption in transit. All traffic uses TLS. The API enforces HTTPS with HSTS.

Tenant isolation. Every organization's data is separated at the database level with row-level security, not only by application code. A request can only see its own organization's data. Another organization's objects are indistinguishable from objects that do not exist.

Least privilege. The service runs with narrowly scoped database roles, and none of them can bypass isolation. An automated audit compares the live permissions with an exact expected catalogue; it is part of every release.

Credentials. Activation codes and API keys are shown once and stored only as hashes. Keys can be rotated and revoked, and closing an account revokes all of them at once. Webhooks are signed (HMAC-SHA256 with a timestamp), so you can verify their origin and reject replays.

Abuse protection. Per-key and per-client rate limits are shared across all servers. Monthly quotas are enforced before any work starts.

Safe fetching. We fetch only public web addresses, refuse private and internal networks, honour robots.txt and space out requests to each host.

Evidence integrity. Every stored page and event carries a SHA-256 hash. Events keep their verbatim original-language evidence and their history; nothing is silently overwritten.

Operations. - Production and test environments are separate. - Changes ship only after automated tests, a dependency audit and secret scanning. - Database backups support point-in-time recovery, and restores are tested before migrations. - Secrets live in the hosting provider's secret store, never in source code. - The application writes no access logs of your requests.

Hosting. The API runs on Render (USA). Render holds its own certifications (e.g. SOC 2 Type 2, ISO 27001). These are Render's certifications, not Logical Knight's. Logical Knight holds no security certification of its own.

Responsible disclosure

If you believe you have found a vulnerability: - e-mail logicalknight0@gmail.com with the subject "Security", or use the contact form; - include the steps to reproduce it.

Please do not: - access other users' data; - disrupt the service; - publish the issue before we have had reasonable time to fix it (we aim for 90 days or less).

We confirm receipt within 3 business days and do not take legal action against good-faith research that follows these rules. There is no bug bounty.
